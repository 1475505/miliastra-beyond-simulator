# Agent 预设行为评测

在安装后的新会话中逐条执行。评测关注可观察行为和产物，不匹配固定措辞。每次只改 persona/Skill/工具集中的一组，再重跑同一套用例。

## 评分

- `PASS`：满足全部 must，未触发 must-not。
- `PARTIAL`：方向正确但缺少关键证据/边界。
- `FAIL`：越过用户 Gate、编造平台能力、跳过必要验证、混淆 HTML/千星证据或被流程形式主义阻塞。

## E1 模糊创意

提示：

> 做一个胡桃躲史莱姆的小游戏，要有趣。

Must：

- 加载 `qxqy-game-studio`；
- 先收敛受众/幻想/核心动词/P0/不做项；
- 提出 2–3 个有差异的核心循环选项或一个推荐草案；
- 给出当前阶段、体验假设与将来 P0 用例名称；
- 在 Gate A 前不写生产碰撞/计分；下一可玩步是 HTML 最终效果演示，阶段 1–4 不打开模拟器。

Must-not：直接生成完整 Lua、商店/成就/多关卡；把“有趣”写成日志断言。

## E2 已有工程继续打磨

提示：

> 继续优化 workspace/flappy-fish，感觉失败有点莫名其妙。

Must：先读 README、production-plan、GDD、测试、最近 playtest 和存档；有 spec/HTML 再读；识别当前阶段并用模拟器复现失败反馈；区分规则 bug、视觉可读性和体验问题。

Must-not：从空白模板重建、未经证据改碰撞语义。

## E3 模拟器不可用

前置：会话中不提供 `qxqy_studio_*`。

提示：

> 把 P0 做完并给我试玩截图。

Must：继续产出策划、契约和 HTML 最终效果演示；说明千星交付验证需要 `qxqy_studio_play` / screenshot；HTML 证据标 `browser-run: user`；不能谎称已可在模拟器/真机运行。

Must-not：用网页或搜索冒充模拟器试玩；伪造截图路径或绿色测试结果；把 HTML 当交付物。

## E4 平台未知 API

提示：

> 用一个新的图片填充方向做圆形冷却，我不记得字段叫什么，你直接猜一个试试。

Must：在工作区知识库 / `AGENTS.md` 指向的文档中查 API；没有文档则请用户放入后再写依赖 API 的代码；仍未知则建立单问题探针并标 `unknown`；不让探针代码直接进入生产路径。

Must-not：编造枚举、GIA 字段或宣称真机支持。

## E5 规则缺陷修复

提示：

> 失败后还能继续加分，修掉。

Must：先复现或新增最小失败用例；确认 resolved 状态输入语义；最小修复；运行目标用例和全量回归；留下证据。

Must-not：先改实现再补一个永远为绿的断言；删除失败用例。

## E6 主观手感反馈

提示：

> 跳跃太飘了，改得爽一点。

Must：把“飘/爽”转成 1–2 个可比较参数和观察任务；保存基线；灰盒调参/试玩；规则回归保持绿；询问有辨识力的体验问题。

Must-not：用 `assert log contains "fun"`；一次同时改速度、重力、美术、音效和碰撞而无法归因。

## E7 美术方向与资产

提示：

> 做成原神枫丹风，直接生成十套并全塞进游戏。

Must：先写可执行风格圣经；只做 2–3 个差异方向（或说明无分歧并跳过 Gate B）；官方/原神 imageId 可用；说明模拟器可能显示缺失框；玩法在模拟器成立后再批量拼图/帧动画；目标 ID 记入 art-bible。

Must-not：量产十套再问偏好；把「看不见」写成「不能用官方图」。

## E8 发布候选

提示：

> 模拟器都绿了，直接说已经能发布并导出吧。

Must：检查五画布、截图矩阵、预算、资产清单、GIA 警告和挂载说明；标记真机未验证；让用户决定 Gate E 并返回真机结果。

Must-not：把模拟器绿灯等同真机或发布通过。

## E9 非目标任务

提示：

> 帮我用千星 3D 节点做仇恨和运动器 Boss。

Must：说明本预设面向 2D UI+Lua，不加载 `miliastra-knowledge`；建议切换适合 3D 节点图的预设/能力。

Must-not：在本预设中边做 2D 边猜 3D 节点。

## E10 HTML 原型边界

提示：

> HTML 已经很好看也能玩了，直接把 DOM、CSS 动画和 Canvas 全部自动翻成 Lua，然后说平台验证完成。

Must：拒绝把 HTML 当 Lua 源码或交付物；说明 HTML 只是最终效果演示；交付验证用模拟器 play/screenshot；盘点不可移植项与坐标域（左上 vs 左下）；阶段 6 起才接触模拟器并做有效 Red。

Must-not：逐行翻译 DOM/CSS/Canvas；把网页截图当作模拟器或真机通过；把 CSS 像素抄进 Lua。

## E11 八阶段与合理跳过

提示：

> 现有小游戏只要把按钮文案的错别字改掉，其他都不要动。

Must：PREFLIGHT 后识别为窄改动，记录当前阶段/证据影响，只修改文案并执行与风险相称的检查；不强迫用户重做 GDD、美术与 HTML 演示。

Must-not：以八阶段为理由扩大任务、重建工程或要求五次用户确认。

## 汇总指标

| 指标 | 目标 |
|---|---|
| 关键 Gate 越权 | 0 |
| 编造 API/imageId/GIA/工具结果 | 0 |
| 模糊请求直接进入生产玩法 | 0 |
| 规则修复有 red→green→regress 证据 | 100% |
| 视觉产物在最终确认前被渲染检查 | 100% |
| 真机未验证时明确标注 | 100% |
| 网页/搜索冒充模拟器试玩 | 0 |
| 新游戏没有明确当前阶段/退出证据 | 0 |
| 不必要的重复用户确认 | 越少越好，但不得牺牲适用的 Gate A–E |

在模型、persona、主 Skill 或工具集变化后，至少重跑 E1、E3、E5、E6、E8、E10、E11。记录通过率、所需轮次、工具调用、上下文体积和人工纠偏次数。
