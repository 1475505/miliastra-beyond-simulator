# 4. 准备千星美术参考图和素材

本步骤回答：卡片里的风格用千星的哪些素材和控件实现。

## 输入与适用时机

读取已锁定的游戏卡片、已确认的 HTML 效果和用户提供的参考。风格以卡片为准，本步骤只决定用什么素材实现它。

## 执行动作

1. 写 `docs/art-bible.md`，把卡片的美术、UI、动效维度落到每个关键视觉元素上：
   - 目标素材或图元、目标官方 `imageId` 和模拟器占位；
   - 色值与字号 token；
   - 使用位置与还原方式；
   - 素材来源与用途。

   art-bible 只引用卡片，不重新定义风格。素材条件迫使风格改变时，回步骤 1 修订卡片。
2. 确定素材 ID，对应关系见卡片的[与模拟器能力的对应](game-card.md#与模拟器能力的对应)：
   - **图片**：创作者委托 AI 选图时，用卡片的风格取值在工作区的素材风格标注中检索（如有）；没有委托时，只写图片语义，请创作者提供 ID，不自行填写。
   - **动效**：卡片要求用官方动效时，选界面动效或全屏动效，记下动效索引；编辑器的【选择素材】可按中文名搜索。
   - **音效**：Agent 无法试听。按卡片的声音语义请创作者试听并给出音效 ID，记入 art-bible。
3. 符合卡片的素材确有分歧时（例如两组官方素材都符合卡片），在同一布局和玩法状态下给出少量对比选项，请用户选择；没有分歧就用推荐项。
4. 按会话实际可用的能力，选用像素画、图元拟合、UI 制作或帧动画 Skill。成本高的拼图或帧动画先做关键样本，批量制作随步骤 5 的进度推进。
5. 写 UI 还原规格（见下）。

模拟器的预览范围见[素材说明](../../../../../studio/docs/image-assets.md)：静态 UI 图库（1,543 个，其中 `100001–100006` 用基础图元代理）和元件图标（2,949 个）都能按需下载预览，所以官方静态图在模拟器截图里就能对照卡片。道具、装备、技能等其他图片来源显示缺失框；下载失败时，截图结果的 `assetWarnings` 会标出来源和 ID。九宫格、动效和实际视觉效果仍以真机为准。

### UI 还原规格

使用千星坐标（原点在左下、Y 轴向上，锚点取值 0–1）；不写 DOM 选择器、CSS 类或 JS/Lua 函数名。

| 字段 | 含义 |
|---|---|
| `id` / `kind` | 稳定的控件名，以及 `container/image/text/button/progress` 等目标类型 |
| `parent` / `anchor` / `offset` / `size` | 控件树与跨画布布局 |
| `styleToken` / `assetId` | 引用卡片色板、字号、间距和资产清单 |
| `visibleWhen` / `action` | 可见状态与抽象的玩家动作 |
| `motionIntent` | 触发条件、时长、曲线和降级方式 |

还原方式优先采用 Lua 实例化基础模板、再配置属性，见 [步骤 5](05-lua-implementation.md#接入模拟器与搭建骨架)。HTML 与 Lua 可以使用不同的适配层，但状态、动作、控件和资产的稳定 id 必须一一对应；网页坐标不得进入 Lua。

## 产物与完成条件

- `docs/art-bible.md`、参考图、素材清单和 UI 还原规格。
- 每个关键视觉元素都有目标素材或图元、使用位置和还原方式。
- 未知 ID 和模拟器占位已标注。

## 下一步与回退

进入 [5. Lua 编码实现](05-lua-implementation.md)。还原方案改变了体验时，回 [2. HTML 效果展示](02-html-prototype.md)确认；只涉及素材取舍时，留在本步骤处理。
