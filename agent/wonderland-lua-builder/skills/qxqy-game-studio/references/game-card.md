# 游戏卡片：对齐设计理念

步骤 1 的第一份产物。用它与用户对齐：给谁玩、玩家感受到什么、看起来和读起来是什么样。卡片锁定后，HTML、art-bible、文案和 Lua 的风格都以它为准；改方向先改卡片。

为什么需要：风格维度没写明时，模型会取最常见的值，这就是“AI 味”。卡片把每个维度变成显式选择，并要求每个选择能追溯到锚点。“金样”指有代表性的示范文案，用户确认后作为后续文案的对照标准。

## 交付流程

1. 读取用户的想法、参考图和约束。用户给出的内容原样填入，不为显得有风格而改写。
2. 用户没给风格方向时，先给 2–3 个方向对比（格式见[方向对比](#方向对比)）。各方向至少在两个维度上互斥，例如克制↔夸张、材质感↔几何平涂、有叙述者↔无叙述者；不给同一风格的近似变体。用户事先说明风格交给 AI，或看过对比后回答“你定”时，直接用推荐方向，在卡面注明“风格由 AI 推荐”，卡片照样填全。
3. 按[模板](#模板)写 `workspace/<slug>/docs/game-card.md`。先做一次[子智能体审稿](workflow.md#审稿)并处理问题，再在对话中展示卡面和仍有分歧的维度，请用户确认或修改。
4. 确认后标为 `locked`，记录确认摘要，再写 GDD。之后的改动记入“修订”（日期、原因、受影响步骤），并同步受影响的 HTML、art-bible 和文案表。

已有工程有卡片就复用。没有卡片的旧工程，只在任务涉及风格、文案或新增内容时补卡：从现有画面和文案反推，标为 `observed`，再请用户确认。窄修复（错别字、规则缺陷）不补卡。

## 填写规则

1. **每格写“选择 + 理由”。** 理由引用锚点中的幻想、情感目标、关键词或参照物。写不出理由，说明这格是默认值：重写，或改为 `TBD`。
2. **不确定写 `TBD`，不填折中值。** 卡片可以带着 `TBD` 锁定，但每个 `TBD` 要在卡面的“待定”中列出，由用户决定。进入步骤 2 前，关键状态表中不能再有 `TBD`。只补齐 `TBD` 时不必重新确认整张卡，在“修订”中记一笔。
3. **写具体场景、物件和数值，不写孤立形容词。** 写“雨后石板路的反光”而不是“梦幻”；写色值和时长区间，而不是“柔和”“流畅”。
4. **常见默认可以用，但要写理由。** 维度说明表最后一列是模型不受约束时的倾向。采用其中一项时，在该格说明为什么适合本作；不要把这一列当禁用清单，否则模型会换一套套路。
5. **置换测试。** 题材换成另一个游戏后这格仍然成立，说明太通用，补本作专有的细节。
6. **只写当前制作路线做得出的效果。** 原生图元以平涂为主，靠造型和色彩表达。官方素材的质感和地域由素材决定；工作区有素材风格标注时，用其受控词表（如 `art_style`、`mood`、`palette`、`material`、`motif`、`region`）填写，便于步骤 4 检索。像素和帧动画写明分辨率或帧数预算。图片按工作区 `AGENTS.md` 或开发约束中的选图规定选取；没有规定时，先问创作者是否委托 AI 选图。没有委托时，卡片只记录图片语义，ID 由创作者提供。
7. **不适用的维度写“不适用”及原因**，例如本作没有音效。

## 维度说明

| 组 | 维度 | 要回答 | 常见默认（采用须写理由） |
|---|---|---|---|
| 锚点 | 玩家与场景 | 谁玩、在什么场合玩、熟练度、单局时长 | “所有人、休闲” |
| 锚点 | 一句话幻想 | 玩家在 ___，通过 ___，获得 ___ 的感觉 | 只写玩法，不写感受 |
| 锚点 | 情感目标 | 从感官、幻想、叙事、挑战、社交、探索、表达、消遣中选主 1、次 1，再写一项不追求的 | 什么都要 |
| 锚点 | 关键词 | 3 个关键词，每个写成“是 X，不是 Y” | 可爱、清新、有趣 |
| 锚点 | 参照物 | 1–3 个作品、场景或现实物件，各写借哪一点、不借哪一点 | 只写作品名 |
| 锚点 | 题材与边界 | 角色、地域、世界观元素；不能出现的内容 | 泛奇幻 |
| 锚点 | 制作路线 | 官方素材拼装（图片、动效、音效）/ 原生图元 / 像素重建 / 帧动画，按对象类别分别写 | 不声明，实施时退回图元 + 默认色 |
| 美术 | 画风 | 平涂、笔触、像素、卡通渲染还是官方素材原样，为什么符合幻想 | 扁平矢量 + 圆角卡通 |
| 美术 | 情绪基调 | 用一个具体场景描述整体氛围；各状态的变化写进关键状态表 | 全程“轻松愉快” |
| 美术 | 色彩 | 主/辅/强调/警示/背景的色值；主色取自世界里的什么；哪种颜色只表示可交互；前景与背景如何分离；饱和度、明度、冷暖范围 | 深蓝紫底 + 霓虹强调；多色等量分布；成功用绿、失败用红 |
| 美术 | 造型语言 | 方、圆、尖分别用在哪类对象；主角与配角的形状如何区分 | 一律圆角矩形 |
| 美术 | 质感 | 平涂、纸、石、木、金属、布；由素材还是图元体现 | 纯色或统一渐变 |
| 美术 | 明暗 | 光源方向或明确无光源；对比度；冷暖 | 外发光 + 投影叠加 |
| 美术 | 视角与构图 | 侧视、俯视还是正面；视觉重心；每屏信息密度 | 居中对称，标题在上、按钮在下 |
| 美术 | 母题与地域 | 本作专有的纹样、物件和地域特征 | 星星、爱心、闪光粒子、emoji |
| 美术 | 识别轮廓 | 角色、道具、危险物只看剪影时如何区分 | 只靠颜色区分 |
| UI | 界面隐喻 | UI 是世界里的什么东西（木牌、卷轴、仪表、手账），或明确不用隐喻 | 网页卡片 + 胶囊按钮 |
| UI | 强调层级 | 每屏最多几处强调；主操作怎样最醒目 | 所有元素同样醒目 |
| UI | 文字层级 | 标题、正文、数字的整数字号与颜色，以及与背景的对比；不选字体 | 白色粗体标题 + 灰色小字 |
| UI | 控件状态 | 按下、禁用、选中、冷却如何表现 | 只改透明度 |
| 动效 | 运动性格 | 快脆、软弹、沉重还是飘逸；常用时长区间与曲线 | 所有元素缩放弹跳 + 淡入 |
| 动效 | 反馈强度 | 克制还是夸张；哪个事件配最强反馈，普通事件弱到什么程度；用官方动效还是控件补间 | 每次得分都放礼花、震屏 |
| 动效 | 转场 | 状态切换用切、淡、推还是遮罩 | 统一淡入淡出 |
| 文案 | 叙述者 | 谁在说话（系统、角色、世界里的物件）；怎样称呼玩家 | 无身份的系统腔，或热情客服 |
| 文案 | 语气 | 正式↔口语、热情↔克制、直白↔隐喻、幽默程度各定一点；随状态的变化写进关键状态表 | 热情鼓励 + 感叹号 |
| 文案 | 世界词表 | 分数、生命、失败、重开、关卡在本作叫什么；哪些词保持通用以免难懂 | 分数／生命／关卡／游戏结束 |
| 文案 | 命名 | 游戏名、道具名、按钮名的构词规则 | “××大作战”“星×”“奇幻×” |
| 文案 | 句式与长度 | 按钮和提示的字数上限；感叹号、省略号等标点规则 | 四字词堆砌、“准备好了吗？”、句句感叹号 |
| 文案 | 教学方式 | 画面演示、首局引导还是文字说明；首屏最多几行字 | 开局一大段规则说明 |
| 音效 | 声音材质 | 木、金属、纸、水、人声还是电子；只写语义，不填音效 ID | 通用“叮”声 |
| 音效 | 音乐 | 有无；情绪；是否随状态变化 | 欢快循环，全程不变 |
| 音效 | 关键反馈音 | 成功、失败、重要事件各用什么声音 | 成功“叮”、失败“嘟” |

## 与模拟器能力的对应

卡片只写模拟器和千星能实现的东西。下表说明各维度在模拟器里对应什么，以及写卡片时要注意什么；具体 ID 在步骤 4 选定。

| 维度 | 模拟器里对应什么 | 写卡片时注意 |
|---|---|---|
| 画风、色彩、母题（官方素材路线） | 全部静态 UI 图片和元件图标都能预览，见[素材说明](../../../../../studio/docs/image-assets.md) | 工作区有素材风格标注时用其词表写，步骤 4 才能按词表检索出 ID |
| 反馈强度、转场 | 官方界面动效和全屏动效，编辑器可按中文名搜索，Lua 用 `PlayAnimation` 播放，见[动效说明](../../../../../studio/docs/ui-vfx-playback.md) | 写明用官方动效还是控件补间；MCP 截图不含动效视频帧，效果要在浏览器试玩里看 |
| 声音材质、关键反馈音 | 官方音效 ID 目录，只有 ID 和时长，没有名称，见[音效说明](../../../../../studio/docs/audio-assets.md) | Agent 无法试听，卡片只写声音的语义；ID 由创作者试听后选定 |
| 文字层级 | 文本控件只有字号和颜色，没有字体字段；模拟器默认用本机原神字体渲染，见[字体说明](../../../../../studio/docs/local-fonts.md) | 只定字号、颜色和层级，不选字体 |
| 玩家与场景 | 5 种画布，以 `mobile-16-9` 为基准 | 写明主要设备；审稿截图按它选画布 |

## 粒度示例

示例只示范要写到多细，不要沿用其中的取值。用户原话：“做个钓鱼小游戏，氛围安静一点。”

| 维度 | 太笼统 | 可执行 |
|---|---|---|
| 情绪基调 | 安静治愈 | 像清晨湖边盯着浮漂的那几秒：很静，但随时可能有动静 |
| 色彩 | 柔和的蓝绿色调 | 橙色浮漂 `#E8A33D` 是画面唯一的暖色，只用于可交互物；湖面用低饱和灰青 `#5E7F86`，让浮漂跳出来；警示色只在鱼咬钩的一瞬出现 |
| 失败文案金样 | 太可惜了！鱼跑掉了！ | 线松了，它游走了。 |

## 方向对比

用户没有给出风格方向时，在对话中给出 2–3 个方向，每个方向写成同样的格式：

```markdown
### 方向 A：<名称>（推荐 / 备选）
- 一句话：
- 与其他方向的关键差异：<维度>=<取值>；<维度>=<取值>
- 色板：主 / 强调 / 背景（色值）
- 金样：开局 / 首次成功 / 失败 各一句
- 适合 / 风险：
```

各方向的金样和色板对应同一局游戏的同一组状态，用户才能直接比较。
