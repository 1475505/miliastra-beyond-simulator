# 千星 2D+Lua 游戏工作室

目标：交付能在千星奇域真机运行的 Lua 游戏和完整存档。模拟器操作以当前宿主实际提供的 MCP 或 Harness 工具为准。

## 按需读取

1. 首次进入或恢复会话：读 [接入与恢复](references/workflow.md)，完成 PREFLIGHT，确定当前步骤。
2. 只读当前步骤的文档。切换步骤时读下一份，缺信息时回读相关步骤；不预先加载全部七份。
3. 新游戏按 1→7 推进；已有工程从最早缺少证据的步骤继续；窄修复只做受影响的步骤。

| 步骤 | 何时进入 | 完成条件 |
|---|---|---|
| [1. 策划案](references/01-game-design.md) | 创意还不是明确的玩法规则 | 用户先后确认[游戏卡片](references/game-card.md)和 GDD；GDD 写明核心循环、输入、胜负、P0 范围和风险 |
| [2. HTML 效果展示](references/02-html-prototype.md) | 卡片和 GDD 已确认，需要确认画面、操作与节奏 | 用户确认演示；试玩中改动的规则已回写 GDD；记录反馈和不可移植项 |
| [3. TDD 制定测试用例](references/03-test-cases.md) | HTML 已确认，规则已稳定 | 规则到用例的追踪表；每条用例有操作和可观察结果；通过静态/schema 检查 |
| [4. 千星美术参考图和素材](references/04-art-assets.md) | 体验与规则已确认，需要正式美术 | 参考图、素材清单、目标 imageId / 图元和 UI 还原方案 |
| [5. Lua 编码实现](references/05-lua-implementation.md) | 需要搭建、实现或修复游戏 | Lua、完整存档、挂载与架构说明、Red→Green→Regress 记录 |
| [6. 测试](references/06-simulator-testing.md) | 已有可运行版本，需要验证规则与体验 | 用例结果、模拟器试玩与截图、盲测与卡片对照、缺陷回归 |
| [7. 真机试玩验证与 bug 修复](references/07-device-validation.md) | 准备交付或处理真机回传 | 导入挂载与索引校准、脚本更新交接、真机结果和未验证项 |

## 贯穿约束

- **顺序**：先用 HTML（步骤 2）确认体验，再按确认后的规则制定用例（步骤 3），然后准备美术（步骤 4）。步骤 1–4 不打开模拟器、不改存档、不运行 `runCase`。
- **TDD**：有效 Red 只出现在步骤 5，即骨架能运行、只缺目标行为；路径、JSON 和工具故障不算 Red。
- **风格**：游戏卡片锁定后，HTML、美术、文案和 Lua 的风格都以卡片为准；改方向先改卡片。
- **独立检查**：游戏卡片和 HTML 交给用户前，各做一次子智能体审稿；请用户试玩模拟器版本前，做一次子智能体盲测。做法见 [子智能体审稿与盲测](references/workflow.md#子智能体审稿与盲测)。
- **资料**：按 PREFLIGHT 查找并核验官方 2D/Lua API 与指南，遵守工作区 `AGENTS.md`。已有资料直接用，只问缺项；不凭普通 Lua/UI 或 3D 节点图经验猜接口。
- **证据**：每条结果标 `runtime=html|simulator|device`。HTML 只证明体验，模拟器证明规则、布局和交互，平台行为只能由真机证据证明；模拟器通过不等于真机通过。
- **素材与坐标**：官方素材可以用。模拟器能预览全部静态 UI 图片（`100001–100006` 用基础图元代理）和元件图标；道具、装备、技能等其他图片来源，以及下载失败的图片显示缺失框，记录目标 ID，到真机核验。千星原点在左下、Y 轴向上，不搬用 HTML/CSS 坐标。
- **工具**：操作前确认实际工具和 schema，有 `qxqy-simulator` 操作 Skill 时按需读取。没有模拟器工具时可以继续步骤 1–4，但不得声称已通过模拟器或真机验证。

## 决策与交接

- 只在这些事上问用户：游戏卡片（设计理念与风格）、玩法语义、HTML 体验、确有分歧的素材取舍、音效试听、真机结果。实现细节、路径、断言和控件拆分自行决定，不反复问“是否继续”。
- `docs/production-plan.md` 记录当前步骤、退出证据和阻塞项；`records/playtest.md` 记录实际试玩结果和来源。
- 恢复与回退规则见 [workflow.md](references/workflow.md)；各步骤的操作细节只写在对应的步骤文档里。
