# 布局唯一来源方案（历史研究稿）

2026-09-24。四平台唯一来源已实施，当前规则和测试证据以 [Studio README](README.md#json-画布布局与-gia-平台槽) 为准。用户最终要求只支持新版读取：完整存档 version 4，资产 layoutSchemaVersion 2；拒绝旧画布字段和缺失平台，不实现布局迁移。此前“缺失平台槽从标准画布补齐”的局部修复已被替代。

以下保留研究过程，不作为当前实现指令。其中旧布局迁移、差异选择、旧格式备份方案未采纳；API 名称和实施范围以当前源码为准。脚本挂载的既有兼容处理保持不变。

## 决策建议

以 `transformByPlatform` 的四平台 RectTransform 为唯一持久化、可编辑来源。五种画布仅表示视口尺寸；预览、检视器、试玩从对应平台读取相同参数，通过父矩形和锚点求出显示布局。不再保存或写入 `transformByCanvas`，也不在读取时执行比例同步。

这不是把两张表包进一个对象。新工程中不会存在可独立修改的逐画布布局；派生的是当前画布的矩形/渲染结果，而不是另一张需要同步保存的变换表。

| 预览或导出目标 | 权威平台槽 |
|---|---|
| PC 16:9、PC 21:9 | KEYBOARD |
| 手机 16:9、19.5:9、4:3 | TOUCHSCREEN |
| 主机手柄 GIA | CONTROLLER_CONSOLE |
| 移动端手柄 GIA | CONTROLLER_MOBILE |

四槽可以有不同值。唯一来源不表示所有设备必须相同；表示每个设备的变换只有一份定义。

## 代码证据与现有问题

- `ui/authoring.js`：`createNode` / `sanitizeNode` 构造两张完整表，出厂工程手动分别修改它们。
- `ui/sync.js`：`readCurrentTransform` 优先画布表；`syncTransformMaps` 开启同步时投影五种画布，再用标准画布填四平台；关闭同步时只改当前画布和对应平台，其他同平台画布仍保留旧值。
- `ui/project.js`：`writeTransform` 同时回写两表；位置、尺寸、锚点、旋转、重设父级、开启同步都经过这里。
- `ui/inspector.js` 和 `play/compile.js`：预览、属性和试玩通过画布优先的读取函数。
- `gia/codec.js`：`transformData` 和旋转导出警告只读平台表；导入由四个平台槽生成画布表。
- `index.js`：完整存档、单资产 JSON、快照返回 Authoring 对象；出厂资产判断也把两表纳入指纹。
- `editor-ui/index.js`：布局修改使用 patch/inspector DTO，没有直接编辑两表；当前导入提示仅显示泛化 warnings，迁移差异需要专门呈现。

最小复现（当前源码、Windows / Node 22.23.2；使用内存新工程，不写入用户文件）：

1. 默认工程选中 `n2`，关闭同步，切换 `pc-21-9`，设置 `posX=1200`：KEYBOARD 的 offset.x 为 150，PC 21:9 为 150，PC 16:9 仍为 -300；GIA 往返后 PC 16:9 变成 150。
2. 默认工程选中 `n2`，保持同步开启，在 PC 16:9 设置 `posX=900`：PC 16:9 offset.x 为 100，PC 21:9 为 131.25；GIA 往返后 PC 21:9 变成 100。
3. 用户日记 JSON 的平台表为空而画布表完整：旧版填默认值后导出 STAGE 为 150×150；已完成的局部修复解决此入口问题，但无法消除上述正常编辑路径的分歧。

证据状态：`evidence_source=observed`，运行端 `simulator`；上述值直接读取模型和 GIA 解码结果，未证明真机渲染。四平台 wire 结构参考本地 `knowledge/ui/02_UI核心数据结构.md` 的“变换 1/12”及现有 codec；跨设备比例投影是模拟器策略。新方案真机验证为 `device_status=pending`。

## 为什么选平台布局

| 候选 | 结果 |
|---|---|
| 平台权威，画布由锚点派生（推荐） | 直接覆盖 GIA 四平台，保留独立手柄布局，预览与导出使用相同参数 |
| 五画布权威，导出抽取标准画布 | 其他比例的独立布局无法导出，手柄还需额外存储；不能保证往返一致 |
| 平台基底加逐画布覆盖 | 可保留旧预览，但覆盖项无法表示为现有 GIA 四槽，继续产生“预览正确、导出不同” |

推荐方案会改变旧行为：同一平台内不再支持各比例独立摆放，也不再自动保存五份中心比例投影结果。不同宽高比的适配通过锚点、拉伸和必要的 Lua 实现。不能把此项当成无行为变化的字段清理。

## 新读写规则

读取统一为两个入口：`getPlatformTransform(node, platform)` 和 `resolveLayout(root, { canvasId, platform })`。一般画布由 preset 决定平台；显式 platform 参数供手柄槽的内部布局求解使用，不能用键鼠父节点布局冒充主机手柄父节点布局。

`resolveLayout` 只读取变换，再按父子层级调用现有 `computeRect` / 矩阵逻辑，返回 boxes 与渲染指标。检视器、命中、截图、试玩使用同一权威变换；试玩运行时修改仍不写回 Authoring。切画布、get、导出不得修改布局。读取返回副本或受保护只读值，避免调用方绕过写入入口。

编辑操作统一到 `writePlatformTransform`：

1. 在当前视口及当前平台的真实父矩形内，将 pos/size/anchor 等输入求成 RectTransform。
2. 关闭同步：仅写当前平台槽。同平台所有画布随后自然读取新值。
3. 开启同步：当前平台直接保存步骤 1 的结果；另外三个平台按各自父矩形投影一次，再写入各自槽。保留现有像素尺寸及零 sizeDelta 拉伸规则。
4. 当前平台即使处在 PC 21:9，也不能先投影到 16:9 再存储，否则当前视口刚输入的位置会跳变。标准视口仅用作其他目标平台投影的计算基准。
5. 目标基准沿用现有策略：键鼠/主机手柄使用 PC 1600×900，触屏/移动手柄使用手机 1280×720；这是计算基准，不是对真实手柄屏幕分辨率的断言。
6. 打开同步相当于显式执行一次上述跨平台同步；加载一个 `syncAllDevices=true` 的存档不触发同步，避免覆盖 GIA 原有四槽。关闭同步不改变现有值。
7. 同步前先计算所有目标平台的父布局，再一次提交，防止遍历顺序影响结果。父级修改、重设父级遵循相同入口，不在读路径自动修正子节点。

GIA 编解码仅转换四槽。保留当前未支持字段的 warnings，例如旋转不能借此重构被宣称可导出。布局往返一致的验收范围限定为已支持的 RectTransform 字段和同一视口的模拟器几何，不承诺所有 GIA 字段或真机像素一致。

## 旧存档迁移（历史提案，未采纳）

应在原始 JSON 进入 `createNode`、填默认值之前迁移，否则无法区分显式值与旧代码生成的默认值。完整存档和单资产 JSON 共用迁移器；GIA 直接构造权威四槽，不走旧双表冲突决策。

建议完整存档格式升级到 version 4，单资产增加 `layoutSchemaVersion: 2`；不要重用 project.version，它是编辑 revision。序列化仅输出新版权威字段，停止通过展开整个模型对象导出旧双表。旧版仍可读入，未知未来布局版本明确拒绝，不能默默用默认值替换。

| 旧输入 | 处理 |
|---|---|
| 仅四平台表 | 原值保留，不随 sync 开关重新投影 |
| 仅画布表、标准画布存在 | KEYBOARD 取 PC 16:9，TOUCHSCREEN 取手机 16:9；缺失的两个手柄槽由对应标准画布复制，标明为迁移策略 |
| 两表都有且标准画布一致 | 保留四平台值；检查额外比例画布是否存在无法保留的差异 |
| 平台槽部分缺失 | 只补缺失槽，显式手柄值必须保留 |
| 两表冲突，或仅有非标准画布 | 生成迁移诊断，不能根据“恰好等于默认尺寸”猜测哪份较新 |

额外画布差异按相同视口比较有效变换及几何；允许浮点容差，例如 1e-4，不只比较宽高。同步投影产生的旧差异也可能是用户依赖的显示结果，不能当作无价值缓存直接丢弃。

迁移采用“候选工程 + 诊断报告”机制，不立即替换现有工程。无差异的输入直接完成；有冲突时，报告控件路径、平台、冲突字段和两种结果，提供“保留现有导出布局（平台）”或“采用指定画布布局”的明确选择。指定宽屏画布时，选的是它的原始 RectTransform，并说明同平台其他视口将按该参数重新计算；不会保留独立宽屏布局。

该选择仅针对有歧义的旧输入，不增加日常编辑或导出确认。MCP/CLI 可传入迁移策略，未指定则返回结构化冲突，不半途加载；Web/DSH 显示差异报告。原输入以备份/迁移报告附件保留在活动模型之外，不参与预览、编辑或导出，也不写成新工程的第二套布局。源文件不自动覆盖；用户日记原文件属于可自动迁移的情况，旧版重新保存且已填默认值的副本属于冲突输入。

## 改动边界与落地顺序

| 位置 | 工作 |
|---|---|
| 新 `ui/layout-migration.js` | 原始输入迁移、版本识别、差异报告，返回候选结果而不是直接提交 |
| `ui/authoring.js` | 新节点仅构造四槽；出厂工程及 sanitize 删除双写，旧输入兼容移到迁移边界 |
| `ui/sync.js` / `ui/project.js` | 平台读写入口，四平台父矩形求解，同步开关与非标准视口编辑语义 |
| `ui/inspector.js` / `play/compile.js` | 去掉画布优先读取，共用平台权威参数 |
| `gia/codec.js` | 导入直接生成四槽；出口做结构检查，缺槽/非法值明确失败，禁止临时猜测补全 |
| `index.js` / host / Worker | 所有创建、导入、存档加载入口共用迁移；序列化、快照和出厂指纹只读新版模型；迁移成功后原子替换项目 |
| `editor-ui/index.js` / MCP | 冲突报告和选择参数；修改操作仍用现有 patch；内部平台选择能力不要求首期新增手柄编辑 UI |
| 文档与测试 | 更新五画布独立投影的旧要求，标明同平台共享参数；补充迁移与往返测试 |

先实现纯函数及回归，再一次切换所有读写和序列化边界；不能出现“预览用新模型，导出还读旧缓存”的过渡状态。旧字段只能存在于迁移输入/非活动备份中。构建后重启本地服务/重新加载安装包才能进入新版；构建成功不代表当前运行实例已切换。

不修改 Lua Runtime 的 RectTransform 契约，不增加 protobuf 字段，不改脚本挂载或 GUID，不扩展到其他控件属性的重构。

## 验收用例

- 原始日记存档：36 个客户端控件四平台的已支持变换按指定标准画布恢复，STAGE 为 1280×720，标题和按钮偏移保留。
- 四平台值各不相同的 GIA：导入、JSON 保存加载、重导出保持四槽；开关同步不在加载时覆盖差异。
- 五个视口 × 同步开/关 × 独立/整合导出：修改尺寸、位置、锚点和拉伸，GIA 往返后的同视口几何保持一致；使用固定几何预期和 wire 字段检查，不能只由同一套编解码自证。
- 非标准视口编辑：同步关闭只变对应平台，另三槽不变；同步开启当前画布输入值不跳变，目标平台使用自身父矩形。
- 嵌套容器、独立手柄父节点、父级缩放/旋转和 reparent：投影及父矩形选择正确。旋转未支持的 GIA 部分验证警告，不要求无损。
- 空、缺失、部分布局、两表冲突、只有非标准画布、混合资产存档：诊断准确；迁移幂等；失败不部分替换工程；两张旧表不会重新进入新版存档。
- get、切画布、预览、试玩编译、导出多次不改变权威四槽；没有切屏累积投影或浮点漂移。
- 根仓库要求的 `pnpm install --frozen-lockfile`、`pnpm test`，并针对 Web/DSH 迁移提示验证。真机只核对尚未覆盖的新跨宽高比同步行为，不能把模拟器测试当作真机通过。

技术上可集中在 Studio 完成主要改动。风险主要是旧工程对五份独立布局的依赖及迁移冲突处理，不是 GIA 二进制格式。实施前应把上述同平台共享语义作为明确的产品行为变更。
