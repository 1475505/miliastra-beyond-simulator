# 客户端控件支持状态与基础滚动

检查日期：2026-10-02。范围是当前源码中的编辑、Lua 运行时和 Web/DSH/PNG 试玩；下表的“可用”不代表千星真机已验证。11 类控件均可创建、配置公共变换、保存 JSON，并按已知子集交换 GIA。编辑器可创建、Lua 字段可读写和试玩实际有效是三个不同层次。

## 支持矩阵

| 控件 | 当前可用 | 主要缺口 |
|---|---|---|
| 容器节点 | 层级、锚点、位置/缩放/XYZ 旋转投影、显隐/激活、脚本挂载、子控件查询、动态实例与 sibling 排序；`showCursor` 参与光标回调门控 | 导航隔离、按键/点击穿透屏蔽字段可保存/读写，但没有完整对应行为；手柄导航不完整 |
| 文本框 | 文本、字号/颜色/背景/描边、横纵对齐、裁切、Lua 更新；字号自适应、最小字号及统一换行，编辑预览/PNG/Pixi 共用排版 | 富文本未实现；字体度量和自适应细节为下方模拟器策略 |
| 图片 | 100001–100006 六类代理图元、白名单图片素材、颜色/透明度、独立宽高拉伸、XYZ 旋转投影与背面镜像、水平/垂直进度填充；矩形遮罩裁切后代，像素羽化从矩形边缘向内 | 径向填充、遮罩反转、纹理轮廓取形未实现；未知素材显示缺失框。羽化曲线、百分比模式和范围字段是下方模拟器策略 |
| 预设按钮 | 点击、悬停、按下、选中、不可用状态；直接子控件四态；射线/交互开关；光标事件与按键监听 | 官方皮肤/音效未播放；完整手柄导航与焦点外观未实现 |
| 光标检测区域 | 射线命中、进入/离开、按下/抬起/点击、拖拽生命周期、坐标/位移；祖先 `showCursor` 门控 | 单活动指针策略，未完整模拟多点触控；与真机的复杂穿透规则不完全一致 |
| 文本视窗 | 文本显示、字号自适应、统一分行、纵向滚轮/拖动/触摸、滚动条轨道点击和滑块拖动、边界限制、内容变更后重算、PNG/Pixi 输出 | 无惯性/回弹、无手柄滚动；交互/滚动条开关 GIA 映射未核实 |
| 网格视窗 | `RefreshItems` 模板项实例化与复用；横纵向排列、AutoWrap/Fixed；滚轮/拖拽/触摸/滚动条；裁切与命中；`scrollProgress`（含 Tween）、`ScrollToItemAt`、数量/尺寸/间隔/边距/内容长度查询 | 完整实例化，未做虚拟列表；单次最多 2000 项；惯性/回弹/手柄滚动未实现；部分 GIA 配置未映射；布局、索引等采取下述模拟器策略 |
| 模板引用控件 | 公共变换、引用索引保存与读回 | 不会根据引用索引自动实例化/展开目标模板；显式 `game.InstantiateClientUIControl` 是另一条已支持能力 |
| 按键提示 | 公共变换、键鼠/手柄按键字段 | 试玩未绘制按键图标，也不随输入设备自动切换提示 |
| 界面动效 | 公共变换、动效/音效/层级字段；`PlayAnimation` / `StopAnimation` 可调用 | 两个方法仍为空操作，无资源播放、动画视觉和音效 |

公共能力也有保真边界：显示布局是平面投影仿真，混合轴、父子均带倾转的通用三维层级仍采用下述策略；手柄配置存取不代表导航事件/最近邻寻路已实现。字段可写但效果未实现的情况，应以上表和对应渲染实现为准。

## 字号自适应（2026-10-14）

修复前 `adaptiveFontSize` / `minimumFontSize` 可编辑、保存及由 Lua 读写，客户端 GIA 的 `TextConfig(75).adaptive(502)` 编解码也正确，但 scene/paint 未投影这两个字段，PNG/Pixi 始终按配置字号绘制。两行文字、40px 字号、最小 10px、160×40 文本框可复现裁切；此前“自适应未实现”的状态由本节替代。

- `play/text-layout.js` 在本地尺寸中测量并缓存分行；编辑布局、试玩 PNG/扁平 paint/Pixi 共用最终字号和显式行列表。开关、最小字号、文本、尺寸变化均重算并进入增量更新；缩放/XYZ 投影在排版之后应用。Lua `fontSize` 和保存配置保持请求值，不被实际显示字号覆盖。编辑预览将同一结果按画布缩放显示。
- **模拟器策略**：字符边界换行，左右各 2 UI 单位留白，行高为字号的 1.2 倍；文本框按下节另计块占位，自适应在 `[min(最小字号, 配置字号), 配置字号]` 中选能容纳全部行的最大正整数字号；到下限仍溢出时，文本框裁切、文本视窗继续滚动。固定字号不缩小，原有 8px 显示下限移除。文本视窗先尝试适配，无空间时为滚动条保留宽度。字体使用宿主配置或本机回退字体，富文本、官方精确换行/小数字号拟合及抗锯齿未还原。
- API 依据为完整知识工作区本地 `Lua客户端UI脚本API.md` 的 `adaptiveFontSize:boolean` 与 `minimumFontSize:integer`（documented / official_document，本轮未在线核验）；上述拟合算法是模拟器策略，`device_status=pending`，不能由字段名或 PNG 推断真机精确算法。
- GIA 必须按消息类型区分：本项目客户端 `TextConfig(75)` 的自适应为 `502`、描边关闭为 `506`；图片编辑器素材组使用的旧 `TextBox(19)` 才是 `506` 自适应。旧消息的 `503=1` 仍含义未知，不映射为 visible，也不替换新版 `TextConfig.field503=12`。旧素材组 GIA 的完整语义导入不在本次渲染修复范围。
- 自包含回归：`test/text-autosize.test.mjs` 以两行 ×1.2 行高加文本框块占位给出最大字号 13 的独立期望（文本视窗仍为16），覆盖实际 Lua 更新、开关/下限、尺寸、滚动、宽度、中文、换行、投影隔离、PNG 和真实 Pixi 对象；`test/gia-observed-fields.test.mjs` 固定新版原生观察字节，防止套用旧字段号。浏览器字号增量验证合并到 `web/test/local-font.test.mjs`，共用真实字体加载、编辑文字 span 和 WebGL 渲染链路，避免维护第二套临时服务器与打包器。测试属于 observed / simulator，不增加真机渲染证据。
- 本地验证：Windows / Node 22.23.2，`pnpm install --frozen-lockfile`、`pnpm test`（353 pass、9 环境相关 skip、0 fail）及 `pnpm build`（Web/MCP/DSH）通过；随后补充“仅修改自适应/最小字号的非当前资产也须进入 GIA 资产包”回归，字号定向测试 6/6 通过。Edge headless / SwiftShader 浏览器用例单独启用后 1/1 通过。运行中的旧宿主需重启并刷新页面。

### #19 选取字号占位模型（2026-10-18）

用户要求选取 [PR #19](https://github.com/1475505/miliastra-beyond-simulator/pull/19) 中的字号像素占位与自适应部分。来源为作者 `a85dbd1` 的测量报告：字号16/高26放不下一行、16/28可放一行、16/46放不下两行、16/47可放两行、20/56放不下两行、20/57可放两行。报告称 PC UI 缩放1.2，具体客户端版本及原始工程/截图未在本轮取得；`evidence_source=provided_unverified`、运行端 `device`、`device_status=pending`。本文将其作为用户采纳的模拟器拟合模型，不宣布为官方跨字体契约。

- 文本框排版需求：`requiredHeight = 行数 × 字号 × 1.2 + 字号 × 0.25 + 4`。空文本不占高度；`contentHeight` 仍仅是行块高度，`blockInset` 是容纳判定余量，不猜测它如何分配为上下 padding。
- 文本视窗不加该余量，维持自身滚动和可见行策略。未采用 PR 的全局10px字号下限、文本框/视窗共用隐藏门槛、滚动边缘整行跳隐；也不将其两套渲染端裁行逻辑复制进来。
- 宽度用 #20 加载的实际字体 `measureText` 测量，自动换行也参与每个候选字号的高度检查。自适应以二分搜索挑能完整容纳的最大整数字号，低于配置最小字号仍放不下时停在最小字号。Lua/JSON 中请求字号不变。
- 例如160×40、两行、配置40、最小10：字号13需要38.45 UI像素，字号14需要41.1，故选择13。宽度/字号的单位为缩放前画布本地像素；实际屏幕像素随后受画布缩放和父级变换影响，字形着色像素范围还取决于字体，不能把 fontSize 当作每个字的固定宽高。
- 精简验证沿用现有 `text-autosize`、`local-font` 和浏览器字体用例，只加一组独立边界表，避免维护 PR 中重复常量/公式断言及另一套浏览器排版链路。
- 选取版独立整合验证（基于 `8c81030`）：冻结锁文件安装、根 `pnpm test` 通过（360 pass、10 环境相关 skip、0 fail）；Edge headless 的字体/字号与键位浏览器验证3/3，Web/DSH/MCP构建通过。此为 `observed / simulator`，不增加原始真机证据。

## X/Y 旋转投影（2026-10-12）

右侧「变换」可编辑旋转 X/Y/Z，MCP/Controller `set` 支持 `rotationX`、`rotationY`、`rotationZ`，沿用四平台同步开关。JSON 保留三轴；GIA `RectTransform.field508` 的 float field 1/2/3 对应 X/Y/Z，导入导出均保留，零分量继续省略、零向量保留空 message。Lua 方法、字段与 Tween 更新共同进入同一变换链。

单轴依据是 ROTXY-20261011-v2 的 PC 真机截图和 126 条采样（完整知识工作区 `knowledge/fact.md` / `probes/image-rotation-xy-20261011/device-20261011.md`）：矩形图片 X 沿高度压缩/翻面，Y 沿宽度压缩/翻面；90° 侧立无面、120/180° 背面可见，子角标继承，GIA/方法/字段一致。实际客户端版本未提供；不将生成包的 7.1.0 当客户端版本。

- `ui/layout.js` 在轴心处计算正交投影矩阵，极小值归零保证 90° 真正退化。负行列分量保留，不能用正宽高替代镜像。
- DOM 编辑器、编辑 PNG、试玩 PNG/扁平 paint、Pixi WebGL 共用完整矩阵；图片先按本地大小切片/绘制再应用投影。显示更新继续走原场景增量机制。点击选择使用同一逆矩阵，侧立时不命中，可从树选择后修改角度。
- **组合策略**：沿用 Runtime 欧拉角读回的 Z-X-Y 约定，局部按 `Ry * Rx * Rz` 投影，然后在二维层级中组合。它保证 `(120,0,0)` 与真机等价读回 `(60,180,180)` 显示相同；混合轴顺序、父子同时倾转时的深度耦合、非图片控件、命中/裁切没有本次真机依据。当前不保留 Z 深度、透视或深度排序；父子均旋转时不是完整三维场景。
- 长期回归：`test/rotation-xy.test.mjs`（配置/同步/JSON、轴心、PNG、角标、等价角、增量、选择、Pixi 矩阵），`test/gia-observed-fields.test.mjs`（独立 wire 字节）。一次性浏览器验收覆盖真实 WebGL 0/30/60/90/120/180→0 增量和 DOM 镜像，验收后脚本已清理。

构建 `pnpm build` 后，重启旧 Web/MCP/DSH 宿主并刷新页面才能加载新实现。上述实现与回归属于 `observed / simulator`；只将真机已覆盖的单轴图片行为标为 `device_status=passed`。

功能完成时的本地检查：Windows / Node 22.23.2，`pnpm install --frozen-lockfile`、全仓 `pnpm test`（332 pass、9 环境相关 skip、0 fail）与 Web/MCP/DSH 构建通过；新增浏览器用例另用 Edge headless / SwiftShader 执行 1/1 通过。2026-10-12 发版清理前再次用 Edge 验收三轴显示、索引批量校准及两条 Lua 同步路径，4/4 通过，再删除一次性浏览器脚本。外部原始 ROTXY2 GIA 用独立复核脚本导入→导出→运行，126 次三轴采样与真机转录一致，原包与源码哈希不变；该外部复核不作为仓库测试依赖。

## 基础矩形遮罩（2026-10-11）

MASK v1 的 PC 真机回传确认：`enableMask` 裁切图片的后代，不裁切兄弟；`imageColor` alpha=0 不取消遮罩。像素羽化从对应两边向内衰减，羽化宽度 0 仍是硬边。真机两组软边并非逐像素相同：不透明遮罩组有较亮条带，具体合成过程未确认，详见完整工作区 `knowledge/fact.md` 的 MASK v1 条目。

当前模拟器策略：矩形取形、线性羽化；按遮罩身份先合成整组（包括图片自身），再应用一次覆盖率，嵌套逐层相乘；遮罩宽高非正数为**空覆盖**，与关闭遮罩区分。百分比模式暂按边长换算宽度，范围字段不参与；这不是官方百分比公式。反转与按纹理透明轮廓取形未实现，点击命中仍用原布局矩形。

- PNG 与 Pixi 的树形及扁平回退使用相同分组边界，重叠子图不会叠加同一个遮罩的覆盖率；独立兄弟遮罩即使几何相同也分别合成。
- PNG 仅分配与画布相交的遮罩包围盒图层，按组读回合成，逆矩阵在组外计算；不再对每个小图元遍历整屏。1600×900、100 个 10×10 图元的一次本机截图从约 29.5 秒降至约 0.08 秒（非跨设备性能承诺）。
- Pixi 外层保留视窗裁切，内层执行图片遮罩；两者独立更新和释放。羽化宽度更新复用纹理，软遮罩纹理单边上限 2048，超大尺寸按纹理缩放显示。
- 回归入口：`test/image-mask.test.mjs` 使用手算像素期望，覆盖重叠/嵌套/兄弟/零尺寸/旋转/高 DPI、Lua 增量、视窗组合与资源回收；`web/test/image-mask-browser.test.mjs` 用同一小型合成夹具核对真实 WebGL 与 PNG，含扁平回退和增量更新。浏览器用例通过 `QXQY_BROWSER` 启用。

上述渲染一致性与性能检查为 `observed / simulator`，`device_status=not_required`；不升级为真机精确羽化曲线或合成顺序已还原。

验证环境：Windows / Node 22.23.2 / Pixi 8.20.0 / `@napi-rs/canvas` 0.1.100。锁定依赖安装和 Web/MCP/DSH 构建成功；全仓测试 326 通过、8 环境相关跳过、0 失败。遮罩浏览器用例另启用 Edge headless / SwiftShader 执行 1/1 通过。一次性渐变演示构建和临时 review 脚本已清理，保留交付文件和真机证据；长期只维护上述必要回归。

## 基础滚动（2026-10-02）

### 使用

- **文本视窗**：在检视器填写超过视窗高度的文本，开启“允许滚动交互”，进入试玩后直接滚轮或拖动。隐藏滚动条仍可滚动。文本变短、字号或尺寸变化会重新测量并限制偏移。
- **网格视窗**：配置“列表项模板索引”、尺寸/间距/排列，在运行脚本中调用 `RefreshItems(itemCount, callback)`。编辑器“预览数量”不自动生成运行条目。只有 `RefreshItems` 管理的模板项随列表移动和裁切；静态子控件保持原位。
- **工具/回放**：沿用 `pointer`，新增 `type: "wheel"`，传 `x/y/deltaX/deltaY`。例如 `{"type":"wheel","x":600,"y":450,"deltaY":48}`。正 `deltaY` 往后滚动；横向列表优先使用 `deltaX`，没有横向量时使用 `deltaY`。`type: "cancel"` 结束当前指针事务，不产生点击。
- 编辑视图保持静态布局；滚动在试玩生效。运行偏移保存在各玩家的运行时控件上，停止/重开复位，不写回 Authoring JSON。

### 明确采用的模拟器策略

这些细节由本次“先基本可用”的需求授权，不宣称为官方行为：

1. 单活动鼠标/触点，无惯性、弹性或手柄滚动；`interactable=false` 禁止原生滚动；网格还检查 `raycastTarget`。滚动命中遵循当前显示树，遮挡在上的可交互控件不会把滚轮传给无亲缘关系的下层视窗。嵌套视窗取命中链中最近的可滚动祖先，不做到边缘后继续传递。
2. 滚动条为简单 8px 轨道、最短 18px 滑块；点击轨道把滑块中心定位到指针，拖动按轨道有效行程换算。浏览器像素/行/页滚轮单位转为画布单位，行按 16 CSS px、页按一视口。内容拖动按控件本地变换换算。
3. 文本在宿主端用本机字体测量、按字符换行，行高 `fontSize × 1.2`；溢出时从顶部开始滚动，内容不溢出时遵循垂直对齐。PNG/Pixi 使用同一份分行和偏移；Pixi 只绘制可见行附近的文字，避免长文本生成超大纹理。字体栅格仍可能不同。
4. 网格项索引 **0 起始**，非本列表项返回 `-1`；`scrollProgress` 限制在 `[0,1]`，0 为顶部/左侧，1 为底部/右侧。`ScrollToItemAt` 的 Top/Center/Bottom 在横向对应左/中/右。
5. 纵向按行填充，横向按列填充；AutoWrap 根据交叉轴空间计算项数；Fixed 使用 `layoutConstraintFixedCount`，最小 1。`padding1X/Y` 暂解释为左/上，`padding2X/Y` 为右/下；cell 最小 1，间距/边距最小 0。这一边距映射尚无真机证据。
6. `RefreshItems` 同步为全部项调用 `(control,index)` 回调，同模板项按索引复用，减少数量时销毁尾项，更换模板后重建；新项激活，模板脚本沿用已有实例化生命周期。没有可见区虚拟化，最多 2000 项；递归刷新同一网格、无效数量/模板明确报错。同步回调完成后释放自身引用。
7. 滚动过程中不额外触发列表项 Click；拖动由内建滚动消费，不同时派发列表项 Drag。滑块盖在列表项之上，输入和显示使用同一视窗裁切。
